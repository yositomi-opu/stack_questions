# 従来の問題文を読みやすいCASTextに変換するための検討

調査日: 2026-09-15。基本変換をアプリに実装済み。外側のsconcatを分解し、未知の部分のみ文字列化を保つ埋め込みにする。
元式を保存し、未編集なら切替解除で復旧する。CASTextからの一般的な逆変換は行わない。
通常のtex2/tex2Lのローカル再定義を確認し、異なる定義は保持する。外部include内の未知の再定義までは判定しない。
以下には実装済みの基本規則と、今後の拡張案の両方を記録する。

## 調査対象

Git管理対象の `001/*.txt` 60ファイルを検索し、問題文・整形関数・参照変数の代表例を確認した。
既存パーサーで抽出できた59ファイル279言語分の問題文では、268件がsconcat、11件が文字列だった。
tex2を含む問題文114件、tex2Lが14件、tex1が14件、tex2rpが2件、ifが12件（重複あり）。
`SetContainIncludeB.txt` はコメントの入れ子／終端の問題により既存パーサーでは抽出できず、この集計から除外。
この数は自動変換の成功率を示すものではない。全問題の実行検証はしていない。

## 変換例

`001/GaussElimRowReducedCheck-A.txt` の日本語問題文:

```maxima
sconcat(tex2L([%_nr, "\\times", %_nc]), "行列\\(A=\\)", tex2(matAp), " を行に関して基本変形すると, ", tex2(matFq), " になる. このとき, \\(p, q\\)の値の組として正しいものを選べ.")
```

CASText入力欄での候補:

```text
\({@%_nr@}\times{@%_nc@}\)行列\(A={@matAp@}\) を行に関して基本変形すると, {@matFq@} になる. このとき, \(p, q\)の値の組として正しいものを選べ.
```

変数名と文章は保持する。上例の `A=` と行列を同じ数式環境へまとめる操作は、基本変換後の整形として扱う。
最初は元の数式境界を保った `行列\(A=\){@matAp@}` でもよい。

## 規則案

| 元の構造 | CASTextへの変換 | 条件 |
| --- | --- | --- |
| 文字列リテラル | 引用符を外し、Maxima文字列のエスケープを1段だけ解く | 文字列を構文として解析する |
| `sconcat(a,b,...)` | 各項を変換して順に連結する | 入れ子も解析。単純なカンマ分割は禁止 |
| `tex2(x)` | `{@x@}` | 関数定義が既知の数式表示用であること。再定義を確認 |
| `tex1(x)` | 既存数式環境内で `{@x@}` | 環境外では従来表示と違うため自動適用しない |
| `stack_disp(x,"i")` | `{@x@}` | 表示環境を確認。他のモードは個別対応 |
| `tex2L([a,"\\times",b])` | `\({@a@}\times{@b@}\)` | リストが直接書かれ、文字列と数式を判別できる場合 |
| 整形済み文字列変数 `QS` | `{@QS@}` | 文字列を返すことが確認できる場合 |
| 文字列を返す条件式 | 例: `{@if sP=sQ then "も" else "は"@}` | 分岐を保持。ブロック構文への書換えは次段階 |
| 選択指示のプレースホルダー | `__SELTYPE__` / `__SELPROMPT__` を維持 | 既存のXML生成処理で対応変数にする |

未知の項を一律に `{@式@}` にしてはいけない。sconcatが数値・リスト等を文字列化する場合と、CASTextが数式として表示する場合では結果が異なる。
文字列になる部分式に限って埋め込みへ残す。型や副作用が判断できなければ、現在の互換移行を維持する。
動的文字列に `{@...@}` や `[[...]]` が含まれていても、埋め込み結果が再度CASTextとして解釈されるとは扱わない。

## 個別対応が必要な実例

- `GaussElimInverseElemMatProd-A.txt`: `QS:tex2L(%_emL1)` のリストは実行時に決まる。まず `{@QS@}` を維持する。tex2rpやremove_parenは独自整形で、標準表示への変更は表示差の確認が必要。
- `MatProdDefB.txt`: `TSqS:tex2L([TSr,"\\times",TSc])` のような間接参照。まず文字列変数として保持する。定義の展開は再代入・評価時点を確認してから行う。
- `PropCompoundA/B/C.txt`: 語句の条件分岐がある。日本語と他言語で語順も違うので、分岐を削除せず各言語を独立に変換する。
- `Sample.txt`: tex1が数式環境の途中にある。周囲の `\(` / `\)` を追跡する必要がある。
- `SpacePlaneParaEq.txt`: 多項式の変数順を指定して表示する独自関数を使用。単なる元式への置換では項順等が変わるため、整形済み文字列を保持する。
- `MatMapPlaneMapsto-B.txt`: 符号を分離するLineEqや、括弧設定を一時変更する整形関数がある。係数1などの省略や括弧形状を勝手に変更しない。

## バックスラッシュ

CASText入力では `\times`、`\(`、`\)` は各1本。
生成するMaxima文字列内では `\\times`、`\\(`、`\\)` とする。
一方、LaTeXの行列改行はCASText入力で `\\`、Maxima文字列内で `\\\\`。
JSONのエスケープはさらに別の層である。全体のバックスラッシュを単純置換するのではなく、文字列リテラルの読み取りと書き出しで処理する。

## STACK APIでの確認

ローカルAPIの `/render` に最小問題XMLを渡し、同一の問題変数で旧式・変換候補・直接CASTextを比較した。
API応答のバージョンはSTACK Maxima `2026062900`、STACK API `2026062900-2`。

```maxima
%_nr:2; %_nc:2;
matAp:matrix([-1/4,p],[1,2]);
matFq:matrix([q,-2/3],[0,1]);
```

- 上記変換例を `castext("...")` に格納した結果と、問題文に直接書いたCASTextの出力本文が一致。
- 数式内の `A={@matAp@}` は数式環境を二重にせず、同一環境に行列を出力。
- 旧tex1/tex2では `-\left(\frac{1}{4}\right)`、変換後は `-\frac{1}{4}`。-2/3も同様。
- 手書きの `\(\begin{array}{cc}1&2\\3&4\end{array}\)` をcastext文字列へ格納して、行列改行の2本が維持されることを確認。

検証はAPIが返すHTML/LaTeXまで。ブラウザでのMathJax描画、全60問題の実行・採点は未検証。
条件分岐や未知の独自関数の変換は設計案であり、このAPI検証には含めていない。

## 実装順序案

1. sconcat・文字列・既知のtex2・リテラルtex2Lを解析し、変換候補を作る。変換できない理由も返す。
2. 元式と候補を比較できる操作として提供し、元式の復元情報を保持する。
3. 数式環境の内外、引用符、行列改行、入れ子、再定義された関数について回帰テストを追加する。
4. 代表問題を複数seed・各言語で旧式と比較した後、安全に判定できた構造だけ自動移行へ組み込む。

公式仕様: [STACK CASText](https://docs.stack-assessment.org/en/Authoring/CASText/)。
castextの引数には静的文字列を用い、実行時の値は埋め込みで評価する。

実装検証: `node scripts/tests/test_casttext_migration.cjs` で提示例・入れ子・数式環境・独自処理・動的リスト・エスケープ・ローカル再定義を検査。実装関数が生成した提示例のCASTextもローカルAPIで描画応答を確認。数式環境の自動結合は行わず元の境界を維持する。
