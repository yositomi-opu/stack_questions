# stack_questions

[English](README.md) | **日本語**

線形代数および微積分に関するSTACKライブラリと問題テンプレートです。
XML問題集は xml.mathedu.jp で公開予定です。

## MCQ WebAppのセットアップ

ローカルのMCQ WebAppとSTACK APIは、repositoryのルートディレクトリから管理できます。

```sh
make check
make setup INCLUDE_BASE_URL=https://username.github.io/repository/
make start
```

`make check` は、必要なPython、Git、Make、Docker、Docker Composeを確認します。Linuxで実行ユーザーがDocker socketへアクセスできない場合は、権限付与による影響を説明し、対話形式で確認を得た場合にだけ適切なグループ設定を実行します。通常版Docker EngineとSnap版Dockerの両方を自動判別します。これらのmakeコマンド自体は `sudo` を付けず、一般ユーザーとして実行してください。`make install-deps` はOS別のインストール計画を表示し、対話形式で確認を得た場合にだけ実行します。`INCLUDE_BASE_URL` は省略可能です。includeライブラリをfork先で公開する場合や、問題変数を `stack_include` を使って別ファイルに保存する場合に指定してください。主要な問題変数を直接埋め込む方式がデフォルトです。macOS、Windows、Ubuntuでの詳しい手順は、[app/mcq-webapp/README.md](app/mcq-webapp/README.md)を参照してください。

同じUbuntuホストのMoodleへログインした教員だけにWebAppを公開する場合は、[Moodleログインによる保護手順](deploy/moodle-auth/README.ja.md)を使用できます。Moodle 4.5用localプラグインとNginxの`auth_request`で全画面・APIを保護する構成で、LTI登録は不要です。

## MCQ問題

### MCQ問題の作成

実装例については、`001.MCQ-rb.xml` と、その中で読み込まれる `Sample.txt` を参照してください。

MCQ関連のファイルはすべて `001` ディレクトリに配置します。

番号の規則は次のとおりです。

- `001`: MCQ形式の問題
- `005`: MCQを使用しないドリル形式の演習
- `010`: 授業での利用を想定した解説付き演習

MCQを実装する前に、次の点を十分に検討してください。

- その問題でどの数学的概念を確認するのか
- どのような誤答パターン（誤概念）が想定されるのか

想定できる誤答が単純な計算ミスだけである場合、その問題はMCQ形式に適していない可能性があります。その場合は、数値や数式を入力する `005` のドリル形式の方が適切かもしれません。

#### 多言語対応の問題文

問題文は多言語対応の形式で作成してください。

最初に使いやすい言語で問題文を書き、その後、下記のプロンプトを使って多言語連想配列を生成します。

テンプレートシステムが、実行時に適切な言語を自動的に選択して展開します。

#### 多言語対応の選択肢

次の両方を用意してください。

- 正答パターン
- 誤答パターン

選択肢自体を多言語対応にする必要がある場合は、次の変数を使用します。

- `%__CoptL1L`
- `%__WoptL1L`

次の変数の代わりに使用してください。

- `%__CoptL1`
- `%__WoptL1`

テンプレートシステムがこれらの変数定義を自動的に検出し、言語に応じた選択肢を生成します。

#### 多言語対応のフィードバック

フィードバックメッセージは本質的に言語に依存します。そのため、最初から多言語連想配列として作成してください。

今後、対応言語を追加するときには、AIを利用した一括変換を行う予定です。

現在は次の言語に対応してください。

- 英語（`en`）
- フランス語（`fr`）
- ドイツ語（`de`）
- イタリア語（`it`）
- 日本語（`ja`）
- ポルトガル語（`pt`）
- 中国語（`zh`）
- 韓国語（`ko`）
- ロシア語（`ru`）
- スウェーデン語（`sv`）

追加言語への対応に関心のある方がいれば、可能な限り対応します。

### 多言語STACK／Maxima翻訳用プロンプト

あなたは、Maximaコードを使用した多言語STACK問題の作成を支援します。

与えられた日本語のSTACK／Maxima記述を、英語、フランス語、ドイツ語、イタリア語、日本語、ポルトガル語、中国語、韓国語、ロシア語、スウェーデン語に翻訳し、Maxima形式の多言語配列として出力してください。

#### 重要な規則

1. 大文字と小文字を含め、Maximaの変数名をすべて正確に保持してください。
   - `weL` と `WeL` は異なる変数です。
   - `wfeL` と `WfeL` は異なる変数です。
   - 小文字を大文字に、または大文字を小文字に変更しないでください。

2. Maximaの関数名をすべて正確に保持してください。
   例：
   - `sconcat`
   - `tex1`
   - `tex2`
   - `tex2L`
   - `matrix`
   - `addcol`
   - `submatrix`
   - `coeff`

3. プレースホルダーをすべて正確に保持してください。
   例：
   - `__SELPROMPT__`
   - `__SELTYPE__`（旧形式）
   - `{@...@}`
   - `%_...`
   - `MapFRmRn`
   - `OpS`

4. 文字列内の人が読む文章だけを翻訳してください。

5. 次のものは翻訳しないでください。
   - 変数名
   - 関数名
   - プレースホルダー
   - 記号式
   - LaTeX式

6. MathJax、LaTeX、HTML、Maximaの構文をすべて正確に保持してください。

7. すべての括弧、コンマ、引用符、セミコロンを正確に保持してください。
   特に次の点を確認してください。
   - 括弧の対応の誤り
   - コンマの欠落
   - 引用符の欠落
   - 壊れた `sconcat(...)`
   - `[` または `]` の欠落

8. 入力された日本語に `__SELPROMPT__` または `__SELTYPE__` が含まれる場合は、そのまま `__SELPROMPT__` または `__SELTYPE__` として保持し、各言語の文章が文法的にプレースホルダーとつながるようにしてください。

9. 入力にどちらのプレースホルダーも含まれていない場合は、新たに追加しないでください。新しい問題では、文全体を表す `__SELPROMPT__` プレースホルダーを推奨します。

10. 次の順序で、有効なMaxima多言語配列だけを出力してください。

```maxima
[
["en", ...],
["fr", ...],
["de", ...],
["it", ...],
["ja", ...],
["pt", ...],
["zh", ...],
["ko", ...],
["ru", ...],
["sv", ...]
];
```

11. 出力する前に、次の点を注意深く確認してください。
   - すべての変数名について大文字と小文字が正確に保持されていること
   - すべての括弧が対応していること
   - 結果が構文的に有効なMaximaコードであること

#### 入力

```maxima
（ここにSTACK／Maximaコードを貼り付けてください）
```
