1. 概要

本アプリは、リポジトリ内のSTACK問題テンプレート 001.MCQ-rb.xml / 001.MCQ-cb.xml を基礎として、Radio Button形式またはCheckbox形式の問題XMLを作成する。サーバーはPython標準ライブラリで静的ファイルとローカルAPIを提供し、画面処理はHTML/CSS/JavaScriptで完結する。

作成問題文、問題変数、選択肢、フィードバック、正解数、言語を画面で編集する。
変換CSV / TSV / XLSX / 既存XMLを読み込み、編集可能な状態へ復元してXMLを生成する。
検証ローカルSTACK/Maximaで式を評価し、任意のSTACK APIで生成XMLをテストする。

主な利用者

  • STACK問題を作成・編集する教員、教材開発者。
  • 問題パターンや行列サイズなどを変えながら、多数の関連問題を作成する利用者。
  • CSV/XLSXで選択肢データを管理し、Moodle XMLへ変換する利用者。

5. 問題編集仕様

5.1 問題形式

  • Radio: 単一選択用テンプレートを使用する。
  • Checkbox: 複数選択用テンプレートを使用する。

5.2 選択肢データモデル

選択肢はパターン番号、真偽（C/W）、言語別選択肢、フィードバック、値種別（text/CAS）を保持する。同一パターン・真偽を複数行登録した場合は候補リストとして扱う。

5.3 真偽ペアモード

設定動作
有効（既定）各パターンにC/W双方を要求し、同一問題内では一方だけを採用する。フィードバックはパターン単位で共有。
無効正解・誤答を独立表で管理する。各パターンは候補リストとフィードバック1件を持つ。

5.4 多言語

対応言語は en, ja, fr, it, de, pt, zh, ko, ru, sv。基本言語を1つ選び、XMLへ展開する言語を複数選択する。最低1言語を必須とする。

「多言語展開」は翻訳依頼JSONを生成する。利用者がChatGPT等へ貼り付け、返却JSONを画面へ戻して反映する。入力変更後は翻訳結果を古い状態として扱い、再展開を要求する。

6. 入出力仕様

6.1 CSV / TSV / XLSX入力

ヘッダーなしのレコード形式。XLSXは先頭シートを読み込む。

レコード用途主な項目
config問題全体設定question_id, mode, num_options, num_correct, random_correct, correct_counts, require_pairs
qtextL言語別問題文言語、本文
qvar問題変数第3フィールド以降をMaxima式として保持
option選択肢パターン、C/W、任意の言語、本文
feedbackフィードバックパターン、任意のC/W・言語、本文

6.2 CSV出力

  • 「CSV見本」は現在のモード用固定サンプルをUTF-8 BOM付きで保存。
  • 「CSV保存」は現在の編集状態を再読込可能な形式で保存。

6.3 XML入力

  • WebAppメタデータ MCQ_WEBAPP_DATA_BASE64 がある場合、編集状態を正確に復元。
  • メタデータがない旧形式では、管理対象のMaxima代入・言語関連付け・選択肢を解析して復元。
  • stack_include(...) がある場合、参照先の読込と編集用スケルトン生成を試みる。

6.4 XML / include出力

問題IDに基づくファイル名でMoodle XMLを保存する。問題変数を別ファイルに保存する場合、XMLは stack_include("URL") を保持し、共通設定ファイルを別途保存する。既定公開PATHは https://yositomi-opu.github.io/stack_questions/001/ で、XML保存後の調整を想定する。

7. XML生成・ランダム化仕様

  1. 選択された問題形式のテンプレートを読み込む。
  2. 画面状態を検証し、問題変数・内部管理変数・言語関連付けをMaximaコードへ変換する。
  3. 選択肢とフィードバックをC/W・パターン・言語単位で構築する。
  4. 編集状態をBase64メタデータとして問題変数内へ埋め込み、再編集可能性を確保する。
  5. テンプレートへ値を反映し、XMLペインと保存ファイルへ出力する。

ランダム化

真偽ペアモードではパターンをSTACK/Maximaの random_permutation で並べ替え、先頭から正答、続いて誤答を割り当てる。同一パターンのC/Wが同一問題に同時出現しないようにする。

正解数のランダム化を有効にすると、指定候補（例: 1, 2, 3）から正解数を選ぶ。固定モードでは入力された正解数を使用する。

8. ローカルCAS評価仕様

8.1 評価フロー

問題変数・CAS選択肢→/api/maxima/evaluate→STACK対応Maxima
  • 問題変数のトップレベル代入から変数名を抽出する。
  • 選択肢の値種別がCASの場合、その式も同一評価コンテキストで評価する。
  • 型（matrix/list/number/string/symbol/expression）、リスト長、評価値を返す。
  • CAS式がリストと判定された場合、XML生成でも候補リスト式として扱う。
  • 問題変数または選択肢変更後は結果を「再評価が必要」とする。

8.2 読込ライブラリ

ky_linear_algebra.mac、tex_library.mac、mcq_template_pre.mac、および設定済みSTACKコードを読み込む。stack_include はローカル参照へ解決して評価する。

8.3 STACK用Maxima

  • 通常Maximaは MAXIMA_EXECUTABLE、PATH、Windowsの一般的な配置順で検出。
  • STACK clone先と生成物を .local-config.json に保存。
  • dump.txt を基にダンプ済み実行ファイルを生成し、通常Maximaより優先。
  • ダンプ生成不可時は評価ごとのSTACK通常読込へ自動フォールバック。

9. STACK API連携仕様

操作外部ルート仕様
接続確認POST /render最小確認用XMLを送り、JSON応答を受信できることを確認。
生成XMLテストPOST /test現在の生成XMLを送り、メッセージと応答詳細を表示。
  • 入力はSTACK APIのベースURL。末尾の /stack.php、/render、/test 等は除去して正規化。
  • URLはブラウザのlocalStorageへ保存し、次回復元する。
  • ブラウザのCORS制約を避けるため、外部通信は server.py がプロキシする。
  • HTTP/HTTPSのみ許可し、資格情報を含むURLは拒否。タイムアウト30秒、応答上限2 MiB。

11. ローカルAPI仕様

Method / Path要求応答・用途
GET /api/server/statusなしサービス名、PID。重複起動検出。
POST /api/server/shutdownローカル接続のみ--reload 用の安全な停止。
POST /api/maxima/evaluatevariables, variableNames, expressions問題変数・式ごとのok/type/length/value/error。

JSONリクエスト本文は最大512 KiB。Maxima式は最大300件。Maxima評価タイムアウトは12秒。

12. 制約・品質・セキュリティ

  • 既定bind先を127.0.0.1とし、ローカル利用を基本とする。
  • 停止APIは127.0.0.1 / ::1からのみ受け付ける。
  • 外部STACK APIは利用者が指定した信頼できるURLだけを使用する。
  • ローカル設定、STACK clone、ダンプ済みMaximaは app/mcq-webapp/.local* に置きGit管理しない。
  • XML特殊文字、Maxima文字列、CSVフィールドは出力先に応じてエスケープする。
  • 乱数評価は実行ごとに値が変わり得るため、画面値は評価時点の1回分である。
  • 翻訳品質は外部生成結果に依存し、反映前の利用者確認を前提とする。
保守方針: テンプレート構造またはSTACK管理変数を変更する場合、XML新規生成だけでなく、メタデータ付きXMLと旧形式XMLの再読込互換性を確認する。

13. 受入確認項目

  1. OS別ランチャーから初回STACK設定とブラウザ起動が完了する。
  2. Radio / Checkboxの双方でXMLを生成・保存できる。
  3. 真偽ペア有効/無効、固定/ランダム正解数の各組合せで選択肢数が整合する。
  4. CSV/TSV/XLSXを読み込み、CSVへ保存し直せる。
  5. 生成XMLを再読込し、問題ID・設定・問題文・問題変数・選択肢を復元できる。
  6. 多言語依頼JSONの生成と返却JSONの反映ができ、変更時に再翻訳警告が出る。
  7. rand 等のSTACK関数がローカル評価され、変数型・length・値が一覧更新される。
  8. 問題変数別保存でincludeファイルと stack_include 参照を出力できる。
  9. STACK API URLの接続確認と生成XMLの /test 結果表示ができる。
  10. 二重起動時に起動済み案内、--reload 時に停止・再起動が行われる。
